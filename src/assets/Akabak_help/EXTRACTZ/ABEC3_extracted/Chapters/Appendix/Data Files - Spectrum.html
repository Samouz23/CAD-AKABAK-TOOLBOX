General Notes on File-Format

ABEC makes use of the same import-engine as VACS, albeit ABEC only makes use of a small sub-set of all possible Import Control Settings.

A convenient way to create data-files is to use the data-export-feature of VACS. You can use text-or binary format.


If you create data-files elsewhere you would need to comply with a certain file structure, which is explained in the help-system of VACS at

Importing Data

Import Control Settings/Data

Further application notes are available at www.randteam.de/Vacs/Vacs-Docs.

Below are given some remarks from the help-system of VACS.


Text-Format of Data-File

Data Separation

Data-values should be separated by Blanks, Tabs or Commas.

Line Separation

Text files are organized in lines. In a stream of text each line is separated from the next line by a combination of characters called "Carriage Return" and "Line Feed" (13+10).

A semi-colon (;) in between text or numbers indicates also a new data-line. However, a semi-colon (;) at the start of the line marks the line as a comment and gets ignored subsequently.

A line, which starts with a character from the set (; | /) is regarded as a comment and as such ignored.

ABEC also reads files where the "lines" are concatenated and separated by commas. In such a file each "line" is encapsulated by commas. Internally ABEC will convert a single-line-file to a multiple line-file. For example

  "xxxx...","yyyy...","zzzz...",...

will be converted to:

  xxxx...
  yyyy...
  zzzz...
  ...

Floating Point Numbers

Floating point numbers are assumed to be in SI-units. The decimal separator is a point (.) or a comma (,). Thousand separators are not supported. SCI-computer notation is fine, for example 1e3 for 103. The mantissa can have up to 15 digits, i.e. double precision. The minimum and maximum absolutes are 10–300 and 10300.

If the interpreter encounters data-lines with "NaN" or "INF" (case insensitive) then the associated line is skipped.

Single Spectrum

For a spectrum-text-file the first column are frequencies in Hz. The second and third column are typically real- and imaginary part.

     2.0000000e+01     -1.1150935e-03   1.2923543e-04
     2.0138773e+01     -1.1660599e-03   1.6439579e-04
     2.0278508e+01     -1.2303389e-03   2.1322478e-04
     ...

To be able to distinguish between different complex notations, we need a Import Control Setting at the top of the file. For example if these data represent real and imaginary parts then

     Data_Format=Complex
     2.0000000e+01     -1.1150935e-03   1.2923543e-04
     2.0138773e+01     -1.1660599e-03   1.6439579e-04
     2.0278508e+01     -1.2303389e-03   2.1322478e-04
     ...

As already mentioned, please refer to the documentation of VACS for details of the Import Control Settings.

Multiple Spectra

As demonstrated in Example Pressure_Box, it is also possible to import data-sets with multiple ordinates, for example for directivity data. In this case we assume all data are compiled within a single file. Either as a concatenation of single data-sets or as one data-set with multiple columns. In any case we assume the same set of values for the abscissa ie frequencies.
