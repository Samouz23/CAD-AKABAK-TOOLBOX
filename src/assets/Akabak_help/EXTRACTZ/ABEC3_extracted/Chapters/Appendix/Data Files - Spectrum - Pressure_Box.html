Pressure_Box defines an ideal pressure source for the Boundary Element Analysis and for the Direct Sound Analysis.

Pressure_Box allows to specify directivity-files, one for the horizontal and one for the vertical plane. The specification is done with the help of the parameters DataFileAlias_Horiz= and DataFileAlias_Vert=. For example

  Pressure_Box
    ...
    DataFileAlias_Horiz=Dir_Horiz
    DataFileAlias_Vert=Dir_Vert

The details of interpolating the balloon-directivity from two principal directivities is discussed in chapter Pressure_Box. Here we want to explain the format of these directivity files.

A directivity-file contains a cluster of frequency response curves. There are spectra for a range of angles. All spectra share the same frequency grid. The angular positions should be along a great arc on the sphere. The horizontal arc runs along the equator and the vertical scan runs through north- and south-pole. The meeting point at the front side is the on-axis direction. For 360 deg arcs each directivity circle should start and end at the rear so that after 180 degree the on-axis point is reached.

The absolute value of the data is not of relevance as each directivity file gets normalized to the on-axis point, i.e. on-axis the frequency response data become one by means of this normalization.

Pressure_Box performs interpolation on the sphere between the horizontal and vertical directivity. However, at the on-axis and at its inverse point a simple mean-value is calculated, because at the rear the two data-files may not converge.

The directivity file should have specified a range of angles, as demonstrated below. For the use with Pressure_Box it does not matter whether the angle runs on theta or phi of the spherical coordinate system. During import ABEC will check which angle varies and which one is assigned constant.

Data_Format=LeveldB_Phase specifies ordinate values to be a level in dB and phase (by default in degree). Together with Data_LevelType=SoundPressure we know it is a sound pressure level.

The first data-column are assumed to be frequencies. The second and third column are SPL- and Phase-values of the first spectrum. The fourth and fifth column are those of the second spectrum and so forth.

The Param_xxx name-space marks the spatial position of each spectrum. Param_Coord_Type=Spherical indicates a spherical coordinate system (mathematical). Using this coordinate system Param_Coord_x1= is the radius of the sphere, Param_Coord_x2= is theta, i.e. the polar angle, and Param_Coord_x3= is phi, i.e. the circumferential angle.

In the above example the spatial variation is in phi. In this case theta should be 90 degree otherwise we would be at the pole and no direction in phi would be possible. Alternatively we could use theta for rotation. In this case phi may have any constant value.


Alternative to the matrix notation you can also create the directivity file in concatenated form. In this case each spectrum forms a section. Each section has the abscissa in the first column and the ordinate components as second and third column.


  Data_Format=Complex

  Param_Coord_x1=1
  Param_Coord_x2=90
  Param_Coord_Type=Spherical

  Param_Coord_x3=-90
    48.6968          0.00387855         -0.00325284
    50.1261          0.00392097         -0.00330659
    ...

  Param_Coord_x3=-85
    48.6968          0.00264268         -0.00497434
    50.1261          0.00286328         -0.00464564
    ...

  Param_Coord_x3=-80
    48.6968          0.00265657         -0.00323919
    50.1261          0.00299562         -0.00331885
    ...
  ...

Just for the purpose of demonstration this example features real and imaginary parts, which is indicated with the help of Data_Format=Complex. For ABEC we do not need anything else because ABEC assumes directivity-data to be sound pressure. Note, as mentioned above, the absolute value of directivity data do not matter because of ABEC will perform a normalization.

Again we need to indicate the type of coordinate system with the help of Param_Coord_Type=Spherical. This can be done once before the first data-set. Eventually we need only to specify varying parameters in front of each data-set.
