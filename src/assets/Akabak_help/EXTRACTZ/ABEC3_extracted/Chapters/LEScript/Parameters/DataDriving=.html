DataDriving=

Home » Lumped Element Scripts

Identifier DataDriving=
Format Floating point number
Purpose Normalization of SPL
Used in Def_MeasRadiator

The network-component MeasRadiator is a two pole. After solving the lumped element network there will be a certain potential at its terminals. This potential can be a voltage, force or a sound pressure, depending what the MeasRadiator component represents. If the MeasRadiator represents a typical loudspeaker driver, for example, then the potential is likely to be a voltage.

The MeasRadiator component simply takes its terminal potential and multiplies it with the data from the file which carries the transfer function or sound pressure response. This product eventually drives its associated Pressure_Points or Pressure_Box:

p = Ust·M

with p: sound pressure at the Pressure_Point, Ust potential difference at the terminals of MeasRadiator and M: value from the file.

Driving Normalization

However, the above formula is valid only if M are values driven with 1V peak. Measurements are typically performed at a different input level and need to be normalized.

You can do the normalization with the help of the Scaling Dialog of Vacs prior exporting, or you can use DataDriving=.

Specification

DataDriving= expects a simple floating point value, which is the value at which the device has been measured. The above formula then becomes:

p = Ust·M/DataDriving


Note, that ABEC calculates peak-values, whereas often driving values are specified as rms-values. In this case simply add the key-word IsRms. For example


  Def_MeasRadiator  'Tweeter'
    DataFileAlias='Imp_Tweeter'
    DataFileAlias='SPL_Tweeter'
    DataDistance=1m,1m
    DataDriving=0.2876  IsRms
