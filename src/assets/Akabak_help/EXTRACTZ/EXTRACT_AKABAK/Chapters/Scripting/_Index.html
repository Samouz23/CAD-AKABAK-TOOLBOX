Introduction

Manual scripting offers a more compact means if compared to specification with the help of GUI-forms. However, the author of the script needs to memorize names of parameters and the logic of specification.
Scripts can be edited with the help of a special Script Form.

Automatic scripting is a technique with the help of which AKABAK is controlled by an external application. This can be Python or SCILab code or a spreadsheet script. If the script is attached to an external file the script gets reloaded if there was a modification.

Syntax of Scripting

Note, the syntax for scripts of BEM- and LEM-parts are similar. Slight differences are explained below.


All script-identifiers are assumed case-insensitive. An exception are units, which should be entered case-sensitive.

All entries are line-oriented. However, you can use ";" as a separator. For example:

  Duct "Vent-Inner"
    EdgeLength=50mm
    WD=200mm;  HD=100mm;  Len=120mm
    ...

"//" is the comment-symbol. Anything behind is regarded as comment and ignored during interpretation. The comment-mode stops at the end of line and ignores any ";"


Indentation is not mandatory but extremely useful. Our recommendation is to indent parameters and section-items by two blanks relative to section-identifiers. Tabs should be avoided, especially if you want to exchange scripts with colleagues.

Scripts of BEM and Observation Parts

Script Sections

Scripts are organized in sections. Each section starts with an identifier followed by a name. If the name has blanks then the string should be set in quotation-marks (use "dbl quotes " or 'single quotes').

The next lines behind the section-identifier are reserved for parameters, many of which are optional (see below). Some sections have at the bottom a list of section-items (see below).

Typing "OFF" in front of a section-identifier disables the whole section.

For example

  OFF Elements "Part II"
    RefNodes="N"
    100    2001  2002  2003  2004  // Floor
    101    2011  2014  2013  2012  // Ceiling
    ...

  Elements "Part I"
    RefNodes="N"
    100    1001  1002  1003  1004  // Floor
    101    1011  1014  1013  1012  // Ceiling
    ...

Parameters

Each section provides a range of parameters, many of which are optional. A parameter typically has following format:

    Indentifier=Value

Syntactically each parameter should form a single line in the script.

Format and unit of the value depends on the type of parameter. In BE-scripts blanks are allowed between identifier and value. In LE-scripts there should be no blank.

Parameters of floating point numbers typically have a unit attached. Details of handling units are explained in this chapter.

Value can be a floating point number, string, integer or a special word.

At some places multiple values can be entered. Each such item should be separated by a blank, tab or comma (but not ";", which is equivalent to a new line).

Parameter-values can itself contain "identifier-value" pairs, for example Position=.

For example

  Control_Solver
    Frequencies = 1Hz, 100Hz  // List of floating point numbers with unit
    Sym=x                     // "x" special word
    ...
  Diaphragm  "D1"
    EdgeLength= 15cm, 1cm
    DrvGroup=1001
    HasBaffle=false;   tb= -10mm
    dD=200mm;  hD1=50mm;  dD1={ 0.3*0.2 }
    Position=  theta=90   phi=0   Rot=30

Lists of Section-Items

At the bottom of the section, ie behind the parameters, have some sections a list of items. Internally, each such item produces a copy of the section with all its parameters. For example, each item of section Elements forms an Element, each item of Driving_Values assigns a value to a DrvGroup and so on.

Syntactically each section-items should form a single line in the script.

Each section-item itself is a list of identifier=value sub-items. At some places only values are expected. All sub-items should be separated by a blank or tab. Within a line of a section-item there should be no ";"

Each section-item always has a number as its first parameter, which is the "name" of this section-item. The name should be unique.

For example

  Nodes N1
    Scale=1mm
    1001    0     0     0
    1002    1.0   0     0
    1003    0     1.0   0
  Radiation_Impedance
    GraphHeader="Radiation Impedance"
    BodeType=Complex
    RadImpType=Normalized
    101    1001     1001   ID=101
    102    1002     1002   ID=102
    103    1001     1002   ID=103

Embedding Scripts

Solving- and observation-scripts allow embedding further scripts, see parameter File=. File= does not belong to a particular section. For example:

File="Nodes.txt"

  Control_Solver
    f1=10Hz;  f2= 100Hz;  NumFrequencies=10;  Abscissa=lin
    Sym=x
    MeshFrequency=100Hz
    ...

Lumped Element Scripts

The syntax is intentionally designed to be as compatible as possible to the legacy system Akabak v2.1. Because of this, the syntax in the LE-scripts slightly differs from the syntax of other input-scripts.

Differences

  • Multiple parameters are allowed in one line - no ";" is required.
  • Identifier=Value pairs should have no blanks.
  • Units are mandatory.

See also chapter LE-Scripts.


For example


  Def_Driver "SP38"
    Re=6.86ohm   Le=2.75mH        fre=4.84kHz  ExpoRe=2.9  ExpoLe=0.775
    Mms=68.5g    Cms=0.108e-3m/N  Rms=4Ns/m    Bl=19.65N/A

  Def_Driving "Voltage source"
    Value=1V  IsRms

  System "S1"
    Resistor "Rg"
      Node=1=2   R=1ohm

    Driver "Drv1"  Def="SP38"
      Node=2=0=20=30    DrvGroup=1001,1002

    RadImp "Front"
      Node=20    DrvGroup=1001

    RadImp "Rear"
      Node=30    DrvGroup=1002
